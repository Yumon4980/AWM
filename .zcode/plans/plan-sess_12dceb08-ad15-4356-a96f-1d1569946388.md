# 选择器浅/深色主题 + 托盘设置入口 + 设置窗口风格统一

## 范围总览

三个独立但相互支撑的改动：
1. 把选择器（`SelectorWindow`）的硬编码颜色全部迁移到 `DynamicResource`，让浅/深色主题真正能切换。
2. 把"设置"入口从选择器标题栏移到托盘右键菜单。
3. 调整设置窗口的视觉语言（圆角列表 + 主题色），让它和选择器风格统一。

`ConfigWindow`（仅命令行 `--config` 唤起）不在本次范围。`HostWindow` 是 `Visibility="Hidden"` 的零尺寸接收窗口，与本次无关。

## Phase B — 迁移 `SelectorWindow.xaml` 硬编码颜色

**位置**：`src/AltTabReplacer.App/SelectorWindow.xaml`

按 A.1 节键名一对一替换 XAML 中所有 `#FFxxxxxx` / `White` / `Black`。逐行替换，**只在改这一处时**——保持其它结构 / 触发器 / 绑定不动。

替换样例：
- `Foreground="#FFDDDDDD"` → `Foreground="{DynamicResource TextForeground}"`
- `Background="#FF1C1C1C"` → `Background="{DynamicResource CellBackground}"`
- `Background="#FF0078D4"` → `Background="{DynamicResource AccentBrush}"`
- `Background="#FF4CC26A"` → `Background="{DynamicResource GroupAccentGreen}"`
- `Background="#33FFFFFF"`（半透明白） → `Background="{DynamicResource HoverBackground}"`（Light 已设 `#22000000`，逻辑等价）
- `Color="Black"`（shadow effect） → `Color="{DynamicResource GhostShadowColor}"` 需先把 Light.xaml 加一个 `Color` token，或保留 `Black`（两种主题下阴影都是黑的也行——降级处理）

**简化 XAML 结构**：
- 删除整个 `<Border DockPanel.Dock="Top">` 标题栏块（含齿轮按钮 + 模板）
- 同步删除 `PART_SettingsBtn` 引用、`SettingsRequested` 关联
- 把 `DockPanel` 替换为单一 `Grid Margin="12,8,12,12"` 直接作为 `PART_Root` 的子元素（标题栏移除后 `DockPanel` 没用了；`Margin` 上 8 替换原标题栏 `Margin="0,0,0,8"` + 旧 `Margin="0,0,12,12"` 的视觉差）

## Phase C — 清理 `SelectorWindow.xaml.cs`

**位置**：`src/AltTabReplacer.App/SelectorWindow.xaml.cs`

**删除**（标题栏齿轮搬走后以下都成死代码）：
- `OnSettingsClick` 方法
- `SettingsRequested` 事件
- `SettingsClosed` 事件
- `SettingsClosedNotify` 方法
- `SuspendIndexCaptureChanged` 仍保留——搜索模式还需要

**改写 `ComposeIconPreview`（L706–731）**：去掉 `static`，构造时通过 `Application.Current.TryFindResource("IconPreviewBackground"/"IconPreviewForeground")` 取当前主题的笔刷。失败回退原硬编码值。

**改写 `BuildGhostContent`（L2470–2512）**：同上，通过 `TryFindResource` 取 `GhostBorderBrush` / `GhostBackgroundBrush` / `GhostTextBrush`。失败回退原值。Shadow 保留 `Colors.Black`（两套主题下都合理）。

**App.xaml.cs 同步清理**：移除 `OnSettingsRequested` 中对 `_selector.SettingsClosedNotify()` 的调用（selector 已不再持有 settings 相关事件），改用现有单例打开逻辑。

## Phase D — 迁移 `RenameDialog.xaml`

**位置**：`src/AltTabReplacer.App/RenameDialog.xaml`

仅 8 个硬编码值，全部替换为 `DynamicResource` 键（`PanelBackgroundAlt` / `AccentBrush` / `TextForeground` / `InputBackground` / `BorderBrushStrong` / `SubtleForeground`）。保留 `White` 用于 `Foreground="White"` 的 TextBox 内部 / `CaretBrush="White"`——`InputBackground` 在两套主题下都是近黑/白，需要区分文字色为 `TextForeground`，CaretBrush 在 Light 下应改 `TextForeground` 才有对比度。

## 关键决策与权衡

- **`ComposeIconPreview` / `BuildGhostContent` 不订阅 `ThemeManager.Changed`**：这两个分别在"选择变化"和"开始拖动"时才生成，每次都通过 `TryFindResource` 读最新值。无需为短生命周期对象维护订阅。
- **`ConfigWindow` 不动**：仅命令行 `--config` 唤起，跟本次主流程无关。后续可单独 PR。
- **`App.xaml` 不动**：主题字典通过 `ThemeManager.ApplyTheme` 合并到 `MergedDictionaries`，不需要预先在 `App.xaml` 占位。
- **不留 `SettingsRequested` 等事件**：纯死代码，全部清理，避免下次误以为有 caller。
